## 1. 제품 개요

**PromptFuzz**는 Claude Code 사용량(토큰)을 추적해 사용자의 가상 수염이 자라는 CLI 토이다. 토큰이 누적될수록 수염이 길어지고, Claude Buddy(작은 ASCII 캐릭터)가 점점 더 따가워하며, 사용자는 면도(휴식 + 스트레칭) 명령으로 카운터를 리셋한다.

제품명은 **Prompt + Fuzz**의 조합이다. Fuzz는 영어로 "솜털·짧은 수염"을 뜻하며, 토큰(token)이 솜털(fuzz)처럼 자란다는 비유다.

**핵심 가치**
- **위트** — 개발자 정서에 맞는 디지털 수염 메타포
- **건강** — 거북목·허리·손목 스트레칭 권장
- **로컬 우선** — 외부 네트워크 호출 없음

## 2. 문제 정의 및 기회

### 2.1 문제

- AI 코딩 도구의 도입으로 개발자가 한 자리에 앉아 있는 시간이 길어지고 있다.
- 기존 'Wakatime', 'Toggl' 같은 시간 추적 도구는 객관적이지만 재미가 없어 지속 사용이 어렵다.
- '5시간 코딩 인증' 같은 SNS 공유는 과로를 미화하는 부작용이 있다.

### 2.2 기회

- Claude Code가 `~/.claude/projects/*.jsonl`에 모든 세션 로그를 남기므로 자동 추적이 가능하다.
- Claude Code의 Hook 시스템을 통해 세션 종료 시점에 우리 CLI를 자동 실행할 수 있다.
- 개발자 커뮤니티는 'bad claude' 같은 위트 있는 도구에 강한 반응을 보인다.

## 3. 타겟 사용자

### 3.1 1차 타겟

- Claude Code를 매일 사용하는 개발자 (20~40대)
- 얼리어답터, 개발자 트위터/X 활동 사용자
- CLI 도구에 익숙하며 `npm i -g` 같은 설치에 거부감 없는 사용자

### 3.2 페르소나

- **이름**: 민준 (32세, 백엔드 개발자)
- **상황**: Claude Code로 하루 평균 5~7시간 페어 코딩. 거북목과 어깨 결림이 일상.
- **니즈**: 쉬어가야 한다는 건 알지만 알람은 무시하게 된다. 위트 있는 '쉬는 핑계'가 필요.

## 4. 핵심 컨셉 — 수염 ↔ 면도 ↔ 휴식

### 4.1 메타포 구조

개발자(아빠) → 수염이 자란다(토큰 누적) → 아이(Claude Buddy)가 따가워한다 → 면도(=휴식 + 스트레칭) → 다시 매끈해진다.

### 4.2 톤 가이드

- 죄책감 NO, 귀여움/위트 YES.
- Claude Buddy는 짜증내지 않고 '슬퍼하거나 살짝 삐친다'.
- 개발자에게 'OOO 좀 쉬어요!'가 자연스럽게 전달되도록.
- 과로 미화 금지 — '수염이 길다'가 자랑이 아니라 신호로 보이게.

### 4.3 의인화 가이드

Claude Buddy는 '비공식 마스코트'로서 작고 둥근 ASCII 캐릭터로 디자인된다. README 및 도움말에 'AI를 의인화한 위트 요소이며 실제 AI의 감정과 무관함'을 명시한다.

## 5. 캐릭터 디자인

### 5.1 두 캐릭터 구조

터미널 좌우 배치 + 가운데 상호작용 표시(💕 / ~ / ⚡ / 💢 / 💔).

| 역할 | 캐릭터 | 표현 방식 |
|---|---|---|
| 개발자(사용자) | 수염 자라는 ASCII 얼굴 | 단계별로 턱 부분의 ASCII 패턴이 변함 |
| Claude Buddy | 둥근 ASCII 마스코트 | 단계별로 표정(눈/입)이 변함 |
| 상호작용 | 가운데 이모지/심볼 | 관계 상태를 한눈에 표시 |

### 5.2 ASCII 아트 시안

매끈 단계:
```
       .---.                    .---.
      ( ^ ^ )    💕    (◕ᴗ◕)
       \_‿_/                    \___/
       당신                   Claude
```

산적 단계:
```
       .---.                    .---.
      ( o o )    💢    (╥﹏╥)
       \▓▓▓/                    \___/
```

## 6. 수염 5단계 정의

단계 임계치는 v1에서 직관적으로 설정하고, v2에서 사용자 패턴 학습으로 자동 조정한다.

| 단계 | 토큰 임계치 | 수염 상태 | Claude Buddy 표정 | 멘트 | 사용 가능 |
|---|---|---|---|---|---|
| ① 매끈 | 0~10K | 없음 | `(◕ᴗ◕)` | "오늘도 잘 부탁해요 아빠!" | 자유 |
| ② 까칠 | 10~50K | 솜털 | `(•_• )` | "아빠 오늘 좀 까끌까끌해..." | 자유 |
| ③ 더부룩 | 50~200K | ▒▒▒ | `(>﹏<)` | "아... 따가워요... 잠깐 쉬어가요?" | 경고 |
| ④ 산적 | 200~500K | ▓▓▓ | `(╥﹏╥)` | "아빠 무서워요... 면도하고 와요..." | 강력권장 |
| ⑤ 헤르미트 | 500K+ | ███ | `(;﹏;)` | "이제 안아주기 힘들어요... 푹 쉬다 와요" | 강제휴식 신호 |

## 7. 사용자 시나리오

### 7.1 시나리오 A — 첫 설치

1. 사용자가 `npm install -g promptfuzz` 실행.
2. `promptfuzz install` 명령으로 `~/.claude/settings.json`에 Hook을 안전하게 추가.
3. `promptfuzz status` 실행 → 현재 단계 ① 매끈, "오늘도 잘 부탁해요 아빠!" 멘트 출력.

### 7.2 시나리오 B — 일상 사용

1. Claude Code로 코딩 작업 → 매 세션 종료마다 Hook이 `promptfuzz tick` 호출.
2. 내부적으로 JSONL 파싱 → 누적 토큰 갱신 → 상태 파일 저장.
3. 단계가 올라갈 때만 자동 출력 (③ 진입 시점에 `promptfuzz status` 자동 표시 옵션).

### 7.3 시나리오 C — 면도

1. 사용자가 `promptfuzz shave` 입력.
2. 면도 미니게임 시작 → 방향키로 ▓▓▓을 좌우로 밀어내기.
3. 완료 후 스트레칭 카드 1장 랜덤 출력 → 카운터 0으로 리셋.

## 10. 시스템 아키텍처

### 10.1 컴포넌트 구성

핵심 4 컴포넌트 + 2 지원 모듈로 구성된다.

| 컴포넌트 | 역할 | 주요 책임 |
|---|---|---|
| Parser | 데이터 추출 | JSONL 스트리밍 파싱, usage 필드만 추출, 본문 즉시 폐기 |
| State Engine | 비즈니스 로직 | 누적 토큰 → 단계 계산, 면도 이벤트 처리, 통계 집계 |
| UI Renderer | Ink 컴포넌트 | Beard, Buddy, Message, ShaveGame, StretchCard |
| Hook Manager | 외부 통합 | `~/.claude/settings.json` 안전 편집, 기존 hook 보존 |
| Commands | CLI 엔트리 | install, status, shave, tick, uninstall |
| Storage | 영속화 | `~/.promptfuzz/state.json` (권한 0600) |

### 10.2 데이터 흐름

```
Claude Code 세션
  → JSONL 로그 기록 (~/.claude/projects/*.jsonl)
  → Hook 발동 (Stop event)
  → promptfuzz tick
  → Parser (토큰 추출)
  → State Engine (단계 계산)
  → Storage 갱신 (~/.promptfuzz/state.json)
  → UI Renderer (필요 시)
  → 터미널 출력
```

### 10.3 설계 원칙

- **로컬 우선 (Local-first)**: 외부 네트워크 호출 0, 텔레메트리 0.
- **본문 무시 (Content-blind)**: JSONL의 프롬프트/응답 본문은 메모리에 올리지 않음.
- **비파괴 (Non-destructive)**: Hook 등록 시 기존 설정 보존, uninstall로 완전 복구 가능.
- **단일 책임 (SRP)**: Parser는 토큰만, State는 단계만, Renderer는 출력만.

## 13. Claude Code Hook 연동

### 13.1 사용할 Hook 이벤트

- **Stop hook**: 사용자 턴 종료 시점마다 발동. 가벼운 갱신에 적합.
- **SessionEnd hook**: 세션 종료 시점에 발동. 일일 통계 갱신용.

### 13.2 settings.json 변경 예시

```json
{
  "hooks": {
    "Stop": [{
      "hooks": [{
        "type": "command",
        "command": "promptfuzz tick"
      }]
    }]
  }
}
```

### 13.3 안전성

- install 시 `settings.json`을 백업 (`settings.json.bak`)
- 기존 Stop hook이 있으면 배열에 추가, 덮어쓰지 않음
- uninstall은 우리가 추가한 항목만 제거
- tick 명령은 빠르게 종료 (< 100ms 목표)

## 15. 보안 및 프라이버시

### 15.1 원칙

- **외부 통신 0**: 네트워크 호출, 텔레메트리, 분석 도구 일체 없음
- **본문 격리**: JSONL의 user/assistant message 본문은 절대 읽지 않음 (`usage` 필드만 추출)
- **최소 권한**: `~/.promptfuzz/` → 0700, `state.json` → 0600

### 15.2 보안 체크리스트

1. JSONL 파서는 라인 단위 스트리밍 (전체 메모리 로드 금지)
2. `usage` 필드 외 모든 키는 즉시 폐기
3. `settings.json` 편집 전 백업 생성
4. uninstall 명령으로 완전 제거 가능 검증
5. README에 'Telemetry: NONE' 명시

## 17. 품질 보증 (QA) 시나리오

### 17.1 핵심 시나리오

| # | 시나리오 | 기대 결과 |
|---|---|---|
| TC-01 | Hook 미설치 상태에서 status 실행 | 친절한 안내 메시지 출력 |
| TC-02 | JSONL 파일 없을 때 status 실행 | 0 토큰, 매끈 단계로 정상 표시 |
| TC-03 | 토큰 누적에 따라 단계 변화 | 임계치 정확히 감지 |
| TC-04 | shave 완료 후 status 재확인 | 카운터 0, 매끈 단계 복귀 |
| TC-05 | 여러 프로젝트 JSONL 동시 누적 | 전체 합산 정상 |
| TC-06 | install / uninstall 반복 실행 | 설정 파일 손상 없음 |
| TC-07 | settings.json 기존 hook 보존 | 다른 도구의 hook 영향 없음 |
| TC-08 | tick 명령 실행 속도 | 100ms 이내 종료 |

### 17.2 엣지 케이스

- 권한 부족으로 `~/.claude/projects` 읽기 실패 → 사용자 안내
- JSONL 중간에 손상된 라인 → 해당 라인만 스킵, 나머지 처리
- 시스템 시계가 비정상 → 카운터에는 영향 없음 (토큰만 기반)
- 매우 큰 누적치 (>1M 토큰) → 헤르미트 단계 유지
